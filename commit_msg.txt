Frontend controls for remixing, so a mashup can actually be heard

RemixPanel.tsx (Visualizer, under Stem Mixer) plus services/api/remix.ts as a
typed client, and GET /api/audio/remix/{name}/file/{which} on the backend.

The serve route is the load-bearing part. Without it the feature is silent: a
remix lands in output/remixes/<name>/, which no other route serves, and
/api/audio/file/... resolves under output/audio/. Verified streaming 882,044
bytes of audio/wav per stem.

The panel offers three one-click presets (Drums A + Vocals B, Intro -> swap,
Blend A + B), editable slots with per-layer track/stem/gain/key-shift/start-bar,
Preview, Build, per-stem playback and a 'Master it' button that runs the Suno
chain over the result. Earlier remixes stay listed and replayable.

THREE DEFECTS THE BROWSER CAUGHT THAT TYPECHECKING COULD NOT

1. The panel picked the wrong songs. It compared the visualizer's library path
   ('Suno-V6-Mini/SunoV6Mini-Ad-Nauseam.m4a') against stem directories
   ('SunoV6Mini-Ad-Nauseam'), so the match always failed and it fell back to
   tracks[0] - alphabetically demucs_test_input, a 10-second demucs fixture.
   The first build laid real drums under a tenth of a second of scratch vocal,
   which reads as the feature being broken rather than as a data problem. Now
   matched on basename, and source B must be >= 30s (durations probed once;
   the backend caches probes on disk so later loads are free).

2. A play button on digital silence. The built-stem list was all four stems, so
   'other' got a button and returned -240 dBFS when no slot referenced it.
   Measured, not assumed. Now only the stems the recipe uses.

3. An eslint-disable for a rule this project does not configure, which errors
   rather than warns. Restructured the seeding effect around an explicit ref
   guard so no suppression is needed.

Also fixed a bug of my own in the panel: preview rendering referenced a
non-existent field.

Verified in a real browser end to end, not just compiled: select track -> panel
seeds SunoV6Mini-Ad-Nauseam at 144 BPM (probed from drums) -> preset -> Build
-> a 10.0s two-song mashup at 144 BPM, Ad-Nauseam drums/bass under
Human-in-the-Loop vocals, streamed and measured audible (drums -5.4 dBFS peak /
40% of frames above -80 dBFS, vocals -11.4 dBFS / 66%).

All 7 gates pass; audio route baseline now 39.
