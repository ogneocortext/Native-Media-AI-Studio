Review the remix code: fix a contract violation, close an API gap

Findings from reading stem_remixer.py and audio_remix.py whole. Where a claim
could be checked, it was checked rather than asserted.

CONTRACT VIOLATION
probe_track required a vocals stem, but list_stem_sources advertises partial
stem sets. A drums-only track was listed as a usable source and then failed to
probe - so the listing promised something the builder could not deliver. Added
_pick_analysis_stem, which prefers drums (most reliable transients) and falls
back through the Demucs order. Verified on a synthetic drums-only track, and
take-the-crown now probes its drums and returns the same 151.999 BPM.

MISSING ENDPOINT
remix_build's docstring claimed /api/audio/enhance-stems accepts a rendered
remix. It does not: that route resolves a library filename under output/audio/
and then finds that file's stems. Tested both a bare name and an absolute path
- 404 both times. Added GET /remix/list (reads the manifests written at render
time, so it cannot drift from what was built) and POST /remix/{name}/enhance
to bridge to the enhancer service, which does take a stem directory. The
docstring now states the actual boundary.

TWO MORE RUNTIME BUGS, both caught by calling the endpoint
- remix_enhance passed an async function to asyncio.to_thread, which returned
  the coroutine object itself; it raised AttributeError on .wav_path.
  suno_enhancer.enhance_stems is already a coroutine and offloads its own DSP.
- EnhanceResult has no `duration` field (success/output_dir/wav_path/mp3_path/
  steps/error). Reading it was the second AttributeError. Duration now comes
  from the remix manifest.

HYGIENE
- Probe cache moved out of output/stems/<model>/<track>/ - a directory owned by
  source_separation that holds only stem WAVs - to output/remixes/.probes/.
  Removed the two stray sidecars my earlier testing had left there.
- crossfade_bars accepted inf/nan: they pass a bare >= 0 and then die inside
  int(round(...)), far from the bad value. Now checked for finiteness.
- Normalised 7 section banners that were missing their two blank lines.
- Dropped a dead `errors` list in _pick_analysis_stem.
- Two more stale "10-step" docstrings in suno_enhancer.py (SunoEnhancer,
  enhance_stems) that the earlier pass over that file missed.

One test failure during this work was my test's fault, not the code's: it left
an empty vocals.wav in place, and STEM_NAMES orders vocals above bass, so the
fallback correctly returned vocals. Fixed the test and said so in a comment.

Verified: 29 tests, all 7 gates pass, audio route baseline 38, and all six
remix endpoints exercised end-to-end including the new enhance route
(missing remix 404, traversal 404, successful master run writing a WAV).
