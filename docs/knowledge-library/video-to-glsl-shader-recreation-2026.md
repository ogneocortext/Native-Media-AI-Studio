# 🎞️ Video-to-GLSL Shader Recreation — shader-skills and the "Video 2 GLSL" Workflow

> [!info] Purpose
> Research note (2026-10-21) on an external open-source project — **shader-skills**
> by gokayfem/gokaygokay — and its showcase workflow, **Video 2 GLSL**: recreating a
> reference video as a single procedural GLSL shader, generated by a coding agent.
> Written to judge fit for this studio's FX shader lane (`features/visualizer/shaders.ts`
> + `ShaderCanvas.tsx`). Figures are labelled **reported** (from the project's own
> README/posts) or **counted/measured** (checked against the repo or this codebase
> on 2026-10-21).

---

## 1. The demo that named the workflow

Reported (Threads summary of the developer's post, 2026-10-21): a 20-second,
19.3 MB animation was recreated as a **156 KB GLSL shader program** generated by
Claude — no video file, no texture images, purely mathematical formulas, with a
seamless loop. The point of the demo is the size inversion: a clip that ships as
megabytes of pixels becomes kilobytes of math that renders at any resolution.

What makes it more than a stunt is that the method is packaged and repeatable —
it ships in the repo as `prompts/video-to-shader-prompt.md` (section 3 below) on
top of a verified function library (section 2).

## 2. The library: shader-skills

Repo: `github.com/gokayfem/shader-skills` — MIT, ~330 stars (counted 2026-10-21),
actively updated. It is **a skill for coding agents** (Claude Code plugin;
`npx skills add gokayfem/shader-skills` for Codex/Cursor/Copilot/Gemini and ~70
others; manual folder copy works anywhere), not a runtime dependency.

- **186 functions across 20 modules** (reported): SDFs, noise, color,
  tonemapping, atmosphere/volume building blocks — each one compiled in WebGL2
  and **numerically tested on the GPU**: SDF Lipschitz bounds (safe to
  raymarch), exactness by surface projection, inside/outside signs, noise
  derivatives vs finite differences, curl-noise divergence, color round trips.
  CI reports 90 property tests × 16,384 samples, plus glslang compilation of
  every module as GLSL ES 3.00.
- **Bundler** (`scripts/glsl_tools.py bundle`): the agent calls functions by
  name (`sdRoundCone`, `softShadow`, `tonemapAgX`); the bundler inlines exactly
  the used functions transitively, in declaration order, producing one
  self-contained Shadertoy-pasteable file.
- **Checker** (`glsl_tools.py check`): lints for WebGL1 leftovers, sine hashes,
  stray `#version` lines, missing `mainImage`; compiles with glslangValidator.
- **Conventions**: `#define DEBUG_MODE 0` (0 final, 1 distance field, 2 normals,
  3 ids, 4 steps, 5 masks, 6 lighting); scene contract `vec2 map(vec3 p)` =
  (distance, materialId); a fixed color pipeline — light in linear, exposure,
  tonemap per AA sample, average, encode sRGB **once**, dither.
- **Evals**: the repo ships a with-skill vs without-skill eval on 6 shader tasks
  (plus 3 near-miss no-trigger tasks) — more rigor than most agent skills, though
  young and author-run.

Why this matters here: agents writing shaders from memory produce exactly the
failures this library eliminates (misremembered formulas, per-GPU hash drift,
double gamma). Its philosophy — *tested building blocks instead of recalled
ones* — is this repo's own "measure, don't recall" rule applied to GLSL.

## 3. The method: the video-to-shader prompt

The repo's `prompts/video-to-shader-prompt.md` turns recreation into a spec
discipline. Target output contract: a single fragment shader, Shadertoy
`mainImage`, GLSL ES 3.00, single pass, no textures, no custom uniforms — driven
only by `iTime`, `iResolution`, `iFrame`.

- **The video is the spec.** The prompt contains no description of the content;
  the agent derives everything from frames and gets the scene breakdown
  **approved before building**. Fields left blank are measured from the video,
  not guessed.
- **Quality bar outranks performance.** FPS is reported, but detail and
  smoothness are never traded for speed without approval; nothing is simplified
  silently.
- **Motion is proven, not eyeballed.** 10-frame strips at 1/60 s spacing around
  every transition and the loop seam; planted feet/wheels/paws never slide
  (proved with a close-up strip of one full gait cycle per gait); gait phase is
  *integrated* (phase = ∫ speed/stride dt) so speed changes never pop the
  phase; states blend as eased weights, never 0/1 switches; secondary motion
  (hair, cloth, tails, foliage) is analytic spring-damped response, because a
  single pass has no state; one gravity per scene, restitution < 1, spin
  matched to roll distance; camera follows with analytic critical damping.
- **Detail is proven too.** Anything covering >10% of frame shows three levels
  (silhouette, secondary forms, surface detail) at 1280×720, plus 4× close-ups;
  every object is decomposed into parts (a flower = head + stem + leaves) — an
  object reduced to its most obvious part fails.
- **Color is measured.** Same region cropped in reference and render; mean RGB
  and spread compared, numbers reported. Every timeline row gets a side-by-side
  at the same timestamp with remaining differences written down.
- **Milestone loop.** After each milestone: critique own renders against the
  reference, fix the 5 biggest differences, re-render — at least 3 passes.
  "A check that fails is listed as failing. It is never 'good enough'."

## 4. Cost routing: run the critique loop on a local vision model

The full quality bar is **vision-call-expensive**: frame strips, close-ups,
side-by-sides and 3+ critique passes per milestone, per clip. On cloud quota
that makes recreation a hero-visual-only tool. The steps split cleanly by what
they actually need:

| Step | Needs | Route |
|------|-------|-------|
| Frame extraction, strips, close-up crops | none — ffmpeg/tooling | programmatic |
| Color mean/spread comparison | none — arithmetic on crops | programmatic |
| Coarse critique passes (layout, palette, big-shape differences, "fix the biggest 5" drafts) | a VLM that will *look* at strips | **local VLM** |
| Initial scene breakdown + part inventory | strong spatial/part reasoning | strong model, once per clip |
| Gait/contact proof judgments, loop-seam sign-off, final approval | fine motion judgment | strong model, at milestones only |

Local candidate (owner's suggestion, 2026-10-21): **Gemma 4 E2B** via Ollama
(`gemma4:e2b`) — effective 2.3B / 5.1B total parameters, multimodal (text,
image, audio), 128K context, ~7.2 GB download at the default Q4_K_M quant
(reported, Ollama guides, Oct 2026). On this studio's GTX 1070 Ti (8 GB) that
is a tight-but-plausible fit with system-RAM offload as slack; the E4B is the
quality step-up if E2B's difference-spotting proves too coarse. One setup trap
(reported): Ollama defaults Gemma 4 to a 4K context window — set `num_ctx`
explicitly or long strip sequences truncate silently.

This is the same tiering the studio already uses for vision review (local VL
model on frames, strong model for judgment calls), and the same prompt lesson
applies: a small VLM defaults to vague praise unless the prompt forces it to
inspect the frames and *name the specific differences* — which the
video-to-shader prompt's strip/side-by-side format already does structurally.

Expected saving: the high-frequency loop (every critique pass, every
intermediate render check) costs local electricity instead of cloud turns;
cloud vision is spent only where its judgment is the bottleneck — breakdown
and sign-off.

## 5. Fit with this studio's shader lane (measured against the tree)

Current state (2026-10-21): `packages/frontend/src/features/visualizer/`

- `shaders.ts` — `SHADER_PRESETS`: fragment shaders as template strings,
  `precision highp float;` + `void main()` over `gl_FragCoord`, uniforms
  `u_time, u_bass, u_mid, u_treble, u_beat, u_energy, u_peak, u_resolution`
  plus the key-palette set (`u_key_hue/sat/conf`).
- `components/ShaderCanvas.tsx` — WebGL1 (`canvas.getContext("webgl")`), sets
  all uniforms per frame; absent uniforms are dropped by WebGL.
- Presets hand-carry their helpers (e.g. Electric Horizon's inlined simplex
  `snoise`) — the exact pattern the library replaces with verified blocks.

**Dialect gap (the real integration cost).** shader-skills emits Shadertoy
ES 3.00 (`mainImage(out vec4, in vec2 fragCoord)`, `iTime`, `iResolution`,
no precision header). The studio consumes WebGL1 ES 1.00 (`main()`,
`gl_FragColor`, `u_*`). The mapping is mechanical — entry-point wrap,
`iTime → u_time`, `iResolution → u_resolution`, add precision header, drop
`#version` — but it is a per-shader adapter step, and any library function
using ES 3.00-only features needs a down-check (the project's own checker
compiles as ES 3.00, so it will not catch ES 1.00 breaks).

**Concrete uses, in order of payoff:**

1. **Preset authorship from reference loops.** Run the recreation workflow on
   a short clip whose look is wanted, adapt the output to the preset dialect,
   then wire `u_bass`/`u_beat`/`u_energy` into its parameters — the same
   hand-built pattern as the existing presets, with a measured reference
   instead of eyeballing.
2. **Verified helpers for existing presets.** Replace hand-copied noise/SDF
   helpers in `shaders.ts` with library blocks where a preset is next touched;
   each replacement is checkable against the library's own property tests.
3. **Deterministic loop material for the wizard.** A texture-free procedural
   shader is tiny, resolution-independent and seam-free — aligned with the
   deterministic-export work (F5) and with shaders' standing role as the
   deterministic fallback when generated assets are flaky.
4. **The prompt as QA tooling.** Sections 0–3 of the video-to-shader prompt
   (frame-strip proofs, measured color diffs, fix-the-biggest-5) transfer
   directly to this repo's visual-QA loop for *any* generated visual, shader
   or not.

**Limits, plainly:** stylized/animated content only — photoreal footage does
not reduce to formulas; per-clip agent cost stays high even with local vision
(the writing and breakdown turns remain); the project is days old at the top
level (the demo and this note are both 2026-10-21) despite shipping evals and
CI; ES 3.00 → ES 1.00 adaptation is unproven per-function until tried on one
real preset.
